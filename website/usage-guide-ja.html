microProject 使い方

対象：0.0.24-beta.1 と現在の実装（2026年10月10日）。Windowsのタスク表・ガント・CCPMの基本操作を説明します。Microsoft Projectとの完全互換は開発目標であり、すべての操作・形式の互換を保証するものではありません。

1. ダウンロード・起動・保存

  1. ダウンロードページでベータ版または安定版を選びます。MSIはインストーラーを実行、Portable ZIPは全ファイルを展開してmicroProject.cmd（またはmicroProject.exe）を実行します。配布物にはJava実行環境を同梱しています。
  2. Ctrl+Nで新規プロジェクトを作成し、名前・開始日を設定します。既存ファイルはCtrl+Oで開きます。
  3. Ctrl+Sで保存します。CCPM設定・履歴を保持するには保存形式に.mpo（MPOF）を選びます。.podにはCCPM拡張状態を保存しません。
  4. 初回はコピーまたはサンプルで試し、保存したファイルを開き直して内容を確認します。

既存のMPP/XML/POD等は「開く」から読み込みます。読込・書出しの対応は形式ごとに異なります。更新用の元ファイルを別途保管してください。

2. タスク表で計画を作る

  1. ガントビュー左側のタスク表で空行の名前セルを編集してタスクを作成します。選択行への挿入はInsert、セル編集はF2を使います。
  2. 期間を入力します（例：2d）。開始日・終了日は依存関係、稼働カレンダー、制約を考慮して計算されます。期間0のタスクはマイルストーンになります。
  3. 子にする行を選択してAlt+Shift+→でインデントします。Alt+Shift+←で戻します。サマリー行の展開・折りたたみで階層を整理できます。
  4. 工程順にタスクを選択しCtrl+F2でリンクします。解除はCtrl+Shift+F2です。先行タスク列でも関係を編集できます。循環するリンクは作らないでください。
  5. Shift+F2でタスク情報を開き、日付、制約、先行関係、リソース等を確認します。

選択・編集・削除

行番号で行を選択します。Ctrl+Spaceは行、Shift+Spaceは列の選択です。コピー／貼り付けはCtrl+C／V、下へのコピーはCtrl+Dです。Deleteは削除、Ctrl+Deleteは内容のクリアなので、選択範囲と確認内容を見て実行します。間違えた操作はCtrl+Z、やり直しはCtrl+Yです。

担当者・進捗

リソースシートに担当者を登録し、タスクに割り当てます。達成率を0〜100%で更新します。遅延を表す場合は達成率だけでなく実績開始と残存期間／残作業を更新します。完了したタスクには実績終了も記録します。

3. ガントチャートで日程を確認する

左の表と右のバーは同じタスクを表示します。表を更新したらバーの位置・長さ・依存線も確認します。Ctrl+Rで再計算できます。

  1. Ctrl+マウスホイールで表示倍率を変えます。見失ったタスクは表で選択してCtrl+Shift+F5でスクロールします。
  2. バー本体のドラッグで予定を移動し、端のドラッグで期間を調整します。進捗部分の操作で達成率を調整します。結果は表の日付・期間・達成率で確認してください。
  3. 依存関係や期間を変更したときは後続工程も確認します。休日、制約、担当者の稼働条件により、操作後の日付が補正される場合があります。
  4. バーの色だけで状態を断定せず、達成率・総余裕時間・実績日付を合わせて確認します。クリティカルパスは依存関係と余裕時間、CCPMのクリティカルチェーンはリソース制約も考慮します。

予定の変更後はCtrl+Z／Yで戻せることと、.mpoで保存・再読込した結果を確認してください。

5.1 CCPM（クリティカルチェーン・プロジェクト管理）入門

CCPMは、タスク間の依存関係だけでなく、限られたリソースの競合も考慮して、実行順序とバッファを管理する方法です。 個々のタスクに余裕を分散する代わりに、プロジェクトの終端と経路の合流点にバッファを置いて管理します。

実習用サンプルとタスク表

20タスクCCPMサンプルの使い方では、完了済み・進行中・未着手のタスクが混在する一般的なシステム導入プロジェクトを使い、CCPMの適用からネットワーク・バッファ表示までを確認できます。 サンプルファイルは説明ページからダウンロードできます。 先行関係に従って後続タスクが開始し、CCPMの表示を安全に試せます。配布時点ではタスクへのリソース割り当てはないため、 まず依存関係を確認し、共有リソースの実習は下記の手順で追加してください。

列 CCPMでの用途
達成率 実際に完了した割合。ガントの完了部分とバッファグラフの横軸に反映されます。
作業時間の達成率 消化した工数の割合です。成果の完成割合である「達成率」とは別に記録します。
残存期間 現実的な残りの見積り。後続タスク、終了日、バッファ消費に反映されます。
実際の開始日 実際に着手した日を記録します。
先行 / リソース名 日程の順序と、共有リソースの競合を確認します。

共有リソースを試すには、リソースシートで「開発者」を 1 名作成し、並行する「実装」と「環境構築」へ各 100% で割り当てます。 プレビューで競合を確認し、適用後に開始日が平準化されることを確認してください。.mpoで保存して再度開き、 リソース名と割り当てが保持されていることも確認します。

CCPMを適用する

  1. プロジェクトを開き、タスクの依存関係、担当リソース、稼働カレンダーを確認します。
  2. プロジェクト → CCPM 設定を開きます。
  3. クリティカルチェーン・プロジェクト管理（CCPM）を使用するにチェックを入れ、プロジェクトバッファの割合を設定します。必要に応じて対象リソースを選択します。
  4. プレビューを押し、変更件数、分割件数、未解決の競合、推奨プロジェクトバッファを確認します。競合が残る場合は、割り当てや平準化条件を見直して再度プレビューします。
  5. 内容が妥当なら平準化を適用を押します。これがCCPMの基準終了日とバッファ量を記録する操作です。
  6. CCPMの設定と共同編集用の状態を保持する場合は、.mpo(MPOF)で保存し、再読込してベースライン・リソース割り当て・平準化遅延が保持されていることを確認します。

ネットワークとバッファの読み方

表示 意味 確認ポイント
クリティカルチェーン リソース制約を含めた終了日に直結するタスク列 遅延がプロジェクト完了日に波及しやすいため、進捗と担当者を優先確認します。
プロジェクトバッファ チェーン全体の遅延を吸収する共通の余裕 残り時間と計画時間を比較し、消費が大きい場合は回復策を検討します。
フィーディングバッファ 非クリティカルな経路からチェーンへ入る遅延を吸収する余裕 流入元のタスクの遅れとバッファ残量を合わせて見ます。

遅れを入力してバッファで判断する

遅れは達成率だけでは表せません。実際の開始日と達成率を更新し、残りに必要な見積りを残存期間または残作業へ入力します。 達成率はガントの濃青部分とグラフの横軸、残存期間は後続タスク・終了日・グラフの縦軸へ反映されます。実績開始・終了は履歴なので、 CCPMの適用や再計算で自動的に動かしません。

日常の確認では、遅れを入力した後にまずプレビューを実行します。 すぐに平準化を適用すると遅れを含む計画が新しい基準になり、バッファ消費を比較しにくくなります。正式な再基準化を決めたときだけ適用してください。 緑・黄・赤の境界は固定比率ではなく、プロジェクト進捗に応じて変わります。初期ほど小さなバッファ消費を慎重に扱います。

バッファ履歴の観測点を訂正する

バッファ状況のグラフを開くたびに現在の分析結果が観測点として履歴に追加されます。誤って追加された点は、グラフ上で点を選択し、この観測を破棄…を押して理由を入力すると通常のグラフとCSV／HTMLレポートから除外できます。 これは物理削除ではなく、観測ID、理由、実行者、時刻をMPOFの監査記録に残す論理破棄です。最新点を破棄する場合は追加の確認が表示されます。

  1. グラフ上の対象点をクリックし、オレンジ色の選択枠と破棄ボタンを確認します。
  2. 観測時刻と進捗／バッファ消費を確認し、必須の理由を入力して確定します。タスク日付、依存関係、CCPMベースラインは変わりません。
  3. Ctrl+Zで観測点と監査記録を復元し、Ctrl+Yで再度破棄します。保存・再読込後も破棄状態が保持されます。
CCPMの分析は現在の依存関係、カレンダー、リソース割り当てを基に計算されます。タスク期間、残存期間、担当者、平準化条件を変更した後は、必ずプレビューを実行してグラフを更新してください。
.podは従来のProjectLibre形式のまま保存され、CCPMの拡張状態は追加されません。CCPM設定を再読込後も保持したい場合や、OneDriveなどの共有フォルダーで同時編集する場合は.mpo(MPOF)を使用してください。
CCPMのショートカット: Ctrl+Alt+CでCCPM設定、Ctrl+Shift+Nでリボンの「クリティカル チェーン」（CCPMネットワーク）、 Ctrl+Shift+KでCCPMバッファ状況、Ctrl+Shift+JでアクティブなガントビューのCCPM表示を切り替えます。 CCPM設定の変更や適用解除は、書き込み可能なプロジェクトでのみ実行できます。

6. 困ったとき

日程が想定と違う

先行関係、制約、稼働カレンダー、残存期間、リソース割り当てを確認し、Ctrl+Rで再計算します。CCPMではプレビューで競合を確認します。

CCPM設定が保存されない

.mpo形式で保存してください。.podにはCCPM拡張状態が入りません。読み取り専用のプロジェクトでは設定・適用を変更できません。

ベータ版の問題を報告する

GitHub Issuesにバージョン、再現手順、期待した結果、実際の結果を記載します。機密情報を除いたサンプルがあると原因を調べやすくなります。
