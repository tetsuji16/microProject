## WBS/XBS inventory and contract

- Desktop entry: Ribbon `RibbonWBS` activates the dedicated WBS view (`TaskInformationRibbonGuiAcceptanceTest.robotNetworkAndWbsRibbonRoutesRenderTheirDedicatedViews`, lines 2603–2645).
- Construction: `Xbs` installs `XbsLayout` into `NetworkModel` and `XbsUI`; `XbsUI` supplies XBS dependency hit-testing through `XbsRenderer`.
- Geometry: `XbsLayout` walks the cached task list in outline order, assigns leaves first, then walks levels bottom-up to center parents over immediate children and create `GraphicDependency` connectors. Its `previous()` cursor restoration is required when a scan encounters the next parent-level row.
- Rendering: `XbsRenderer` adapts XBS-specific stored shape/center/translation to shared `NetworkRenderer`; the shared renderer paints typed dependencies and cached nodes. Offline SVG also creates `XbsLayout`/`XbsRenderer`.
- Interaction: `XbsInteractor` inherits shared network selection/link handling; its product-specific link creation/reorder actions move a node in the task hierarchy and open the dependency dialog. The hierarchy layout is a distinct contract from PERT's dependency layout; apparent renderer reuse does not establish duplicated geometry.
- Provenance: historical OpenProj-derived typed graph traversal was modernized at `8369053e0` and documented in `docs/audit/openproj-java25-modernization.md`. The current XBS-specific hierarchy geometry remains separate; no duplicate calculation justified for consolidation was found. The typed iterator change preserved traversal order and hit-testing.

## PERT/network inventory and contract

- Desktop entry: Ribbon `RibbonNetwork` activates `PertView`; `PertView.init` creates `PertChart`, installs a filtered task cache and the `pert` styles. `PertChart` installs `PertLayout` and a horizontal `PertRenderer`; offline SVG `NetworkSVGRenderer` also installs `PertLayout`/`PertRenderer` for `PERT` mode.
- Geometry: `PertLayout` asks `DependencyGraph` to recompute PERT levels, resets node levels from the visible outline/cache levels, then raises every successor to at least predecessor level + 1 by breadth-first propagation. The layout scans cache order, places x from dependency level and advances y whenever the current column is not beyond the prior column. `GraphicNode` stores the PERT shape/center; `PertRenderer` adapts these to shared `NetworkRenderer`.
- Rendering/hit-test: PERT dependency edges remain in the node cache and shared renderer draws them; `NetworkUI` hit-tests shared rendered nodes/links. This DAG placement is distinct from XBS's outline parent/child centering and connector creation, so no duplicate geometry helper is warranted.
- Existing coverage: `NetworkSVGRendererLifecycleTest` initializes/paints PERT and checks cache listener lifecycle but does not assert coordinates. Existing Robot route `TaskInformationRibbonGuiAcceptanceTest.robotNetworkAndWbsRibbonRoutesRenderTheirDedicatedViews` activates Network, requires multiple nodes and at least one dependency, checks network form contrast/readability, and captures dark/light/restored-dark; it does not assert PERT selection, hit-test, zoom, scroll or resize.
- Provenance: `PertLayout`'s placement logic traces via `git blame` to ProjectLibre commit `9b5c2f988` (2019); `DependencyGraph`'s original graph propagation traces to OpenProj commit `d2fa3c20a` (2012). Typed collection/loop modernizations were later made in `e39afa103b` and `d75171a8203915d9247946e0cc14a21bbbf0fe07`; see `docs/audit/openproj-java25-modernization.md`. These are historical provenance records, not separate evidence of MSP behavior.

## Gantt/link inventory and contract

- Rendering path: `GanttRenderer` obtains visible dependencies from the cache, resolves projected predecessor/successor rows, clips links to their endpoint rows, and routes/paints each link with configured start/end arrow shapes. It selects internal/external link color, disabled stroke, and paints cross-project labels. For milestones, selection geometry routes from/to the visible diamond edge rather than the zero-duration center.
- Routing boundary: `DefaultGanttLinkRouting` selects start/end bar edges by FS/SF/SS/FF direction, handles target row floor/ceiling, and has a short vertical-arrow route for nearby FS links. `LinkRouting.routeOrthogonal` explicitly documents Gantt as specialized for dependency direction, arrow floors, and bends; `DefaultNetworkLinkRouting` delegates to the shared orthogonal route. These paths have distinct responsibilities and should not be merged.
- Provenance: Gantt's renderer/routing path traces to OpenProj commit `d2fa3c20a` (2012). Milestone-edge handling was added in `6330c6f037`; cross-project colors and labels in `c66fecc3a5` and `075434730d`. The package consolidation history is `ba91c1191`/`4765e5ff8`. This records lineage, not measured Microsoft Project behavior.
- Existing evidence: `GanttSelectionGeometrySupportTest` verifies a milestone FS link starts at the painted milestone edge. `GanttBarDateDragGuiAcceptanceTest` physically creates a dependency by dragging between hit-tested bars and checks command result, model/projection, FS kind, Undo/Redo and MPO reload; its post-Redo full-window capture supplies the Gantt Robot screenshot. - WBS/PERT GUI comparison: task-graph construction, node coordinate adapters (`getXbsCenter` vs `getPertCenter`), selection resolution, and scroll axis are intentionally view-specific.
