## #1154 workbook reconciliation slice — Progress Lines

The Current Channel workbook row `ProgressLines` is a `button` in `TabGanttChartFormat` / `GroupGanttChartFormat`. Microsoft Learn [Application.ProgressLines method](https://learn.microsoft.com/en-us/office/vba/api/project.application.progresslines) says the command displays the Progress Lines dialog and is equivalent to the Gridlines dropdown command. Microsoft Support [Set the status date for project reporting](https://support.microsoft.com/en-us/project/set-the-status-date-for-project-reporting) documents progress lines for the current date, status date, and regular intervals. The former implementation only toggled one line at status date; it lacked current/status choice, recurring intervals, a settings model, and MPO persistence.

This finite slice adds those settings, renders both a selected reference date and recurring calendar intervals, and persists settings in the MPO settings sidecar. Current date selection uses the project's current date, with today as the unset fallback. Recurring intervals anchor at project start; Microsoft documents regular intervals but not their anchor, so this is an explicit document-derived rule. Custom dates, line-by-line styles/colors, and empirical comparison against installed Microsoft Project are outside this slice. The physical Windows GUI journey clicks the ribbon command, selects current date and recurring lines, confirms a rendered Gantt image change, exercises Undo/Redo, saves through the ribbon, closes the original document frame, and opens the MPO in a new frame. The reloaded frame restores the configured visible state and renders the progress lines. Settings apply/undo/redo go through the project's mutation event/revision boundary; tests cover read-only rejection, undo after save marking the project dirty, undo while another document is active, MPO settings round trip, old MPO documents without this optional setting, and interval boundary generation.

Recurring date generation is limited to the visible Gantt timescale interval and jumps directly to the first interval index intersecting that range; it does not walk each day from project start to the viewport. There is no arbitrary 10,000-line cap. Tests cover month-end anchoring, daily intervals across DST dates, exact visible-range clipping, and a project with more than 10,000 recurring dates.

A review found and fixed a viewport-start edge where moving the estimated recurrence index backward could desynchronize the date and index, dropping later lines. New tests start weekly and monthly viewports between intervals and require all subsequent in-range dates.
