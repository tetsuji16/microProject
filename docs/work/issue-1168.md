### A3 follow-up: MPXJ work-range union and custom contour import

- **Observed from external fixture (not committed):** MPXJ 16.11's `splits9a.mpp` is available in MPXJ's test data. A local read showed Task UID 2 with two work ranges and UID 7 with three; the latter therefore has two intervening work gaps. Those tasks carried unassigned (`ResourceUID` absent/zero) contoured assignments. Other fixture tasks carry actual and remaining work. The fixture was downloaded to a temporary audit directory and is not redistributed here; the MPXJ repository is LGPL-2.1, but that does not establish separate fixture redistribution terms.
- **Specification/API evidence:** MPXJ's timephased guide says task work is rolled up from resource assignments; a task split is a gap in the union, and `Task.getWorkSplits()` reports contiguous task work ranges. It separately describes assignment-level `getWorkSplits()`. See https://www.mpxj.org/howto-use-timephased/ (Split Tasks, lines 1156-1179). This is MPXJ API documentation, not a Microsoft format guarantee. Microsoft's MSPDI task schema still has only the Stop/Resume pair; assignment Type 1/2 timephased rows have separate ownership.
- **Implementation in this slice:** `MspImporter` reads `Task.getWorkSplits()` for gaps and imports an unassigned custom work contour into the existing default assignment. `MpxAssignmentConverter` resets dependent actual/scalar work before rebuilding custom timephased work, then restores actual work; this avoids double counting when source actual + remaining work rows are reimported. `MpxTaskConverter` restores task split intervals and source finish after schedule recalculation.
- **Generated fixture regression:** `customAssignmentWorkWithTwoGapsRestoresTaskGapIntervals` checks three non-contiguous assignment work ranges yield two model task gaps, total work/actual/remaining and finish preservation, unassigned contour import, MPO reload, and MSPDI writer/MPXJ reader roundtrip. `taskWorkSplitUsesUnionAcrossAssignments` has two resource assignments with different individual work gaps; their union is continuous, so the imported task must have no split intervals. Both passed with `--rerun-tasks` on working tree based at `c15b635ef`.
- **External fixture probe:** Import of `splits9a.mpp` completed after the work reset fix; scalar task/assignment totals matched the source for the probed tasks, including 100%-complete work. This probe was temporary and is not an independently reproducible checked-in fixture.
- **Remaining A3 acceptance is open:** No redistributable real MPP multi-gap fixture is checked in; multi-gap import is characterized via generated MSPDI, not an MSP-authored MPP artifact. MPP import of the external fixture is observation only. Export was verified from imported timephased contours; manually created `TaskSplitInterval` export and whether task gaps without corresponding assignment contour data survive MSPDI/MPP have not been established. Also not yet verified across calendars with holidays/resource calendars or multi-resource gaps that partially overlap. Keep A3 open pending those checks; do not infer support for arbitrary manual splits or close #1168.
