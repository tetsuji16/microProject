## Remaining blockers

- A3 remains an implementation and fixture gap: multi-segment MPP/MSPDI import/export has not been proven or implemented. MPXJ 16.11 has `Task.getWorkSplits()`, but the official MPXJ changelog says it returns working-time ranges only; fixture inspection confirms that it is not a representation of the task's nonworking split gaps. The MPP fixtures checked expose a single continuous work range, sometimes alongside one Stop/Resume pair. The pinned MPXJ API provides MSPDI writing and MPP reading, but no MPP writer. Microsoft sources: [Task element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/task-element?view=project-client-odc), [Tasks schema](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/xml-schema-for-the-tasks-element?view=project-client-2016), [TimephasedData element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/timephaseddata-element?view=project-client-2016), and [Task.Split method](https://learn.microsoft.com/en-us/office/vba/api/project.task.split). The schema exposes single Stop/Resume properties and timephased values; it does not document a repeated task split record. This supports the current interoperability limit, not a claim that every MPP encoding has been examined.
- A4/A5 hosted split Robot proof is pending on the final candidate.
