## Remaining blockers

- A3 remains an implementation and fixture gap. Microsoft says Task Stop is the end of the actual portion and Resume is the remaining portion's scheduled restart; assignment Stop/Resume and assignment timephased actual/remaining contours have separate ownership. The Project 2019 Task 3 MPP/MSPDI fixture provides actual paired values, but its task has one work-time range and no model manual gaps; it cannot establish a generic split representation. `MPXConverter` emits task Stop/Resume. `MpxTaskConverter` has no direct reads of these Task fields, but the real fixture imports with matching Task 3 values via assignment/progress state, so the previous packet's claim of a general inbound omission is withdrawn. `getWorkSplits()` summarizes working ranges; no explicit gap payload is exposed by the pinned MPXJ API. Microsoft sources: [Task element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/task-element?view=project-client-odc), [Stop element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/stop-element?view=project-client-2016), [Tasks schema](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/xml-schema-for-the-tasks-element?view=project-client-2016), [TimephasedData element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/timephaseddata-element?view=project-client-2016), and [Task.Split method](https://learn.microsoft.com/en-us/office/vba/api/project.task.split). The schema exposes one Task Stop/Resume pair, not a documented repeated split collection; that does not prove all MPP encodings have been examined.
