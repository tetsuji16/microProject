## Remaining blockers

- A3 remains an implementation and fixture gap, including an inbound omission: `MPXConverter` exports task Stop/Resume, while `MpxTaskConverter` does not import them. Microsoft says Stop is the end of the actual portion and Resume is the remaining portion's scheduled restart; this progress boundary cannot safely be equated with every manual split. Assignment Stop/Resume and assignment timephased actual/remaining contours have separate ownership. MPXJ's `Task.getWorkSplits()` exposes working-time ranges; the fixtures checked do not prove it preserves arbitrary task gaps. Microsoft sources: [Task element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/task-element?view=project-client-odc), [Stop element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/stop-element?view=project-client-2016), [Tasks schema](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/xml-schema-for-the-tasks-element?view=project-client-2016), [TimephasedData element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/timephaseddata-element?view=project-client-2016), and [Task.Split method](https://learn.microsoft.com/en-us/office/vba/api/project.task.split). The schema exposes one Task Stop/Resume pair but does not document a repeated split record; this does not prove all MPP encodings have been examined.
