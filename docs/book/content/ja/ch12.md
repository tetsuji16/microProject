プロジェクト管理ソフトの教科書には、日程表以外に、カレンダー、タスク制約、定期タスク、コスト、出来高、カスタムフィールド、ビュー、レポート、複数プロジェクトなどが含まれることがあります。本書もこれらを学習対象から外しません。ただし、MSPで説明される機能がそのままmicroProjectにあるとは限らないため、確認状況を五つに分けます。

![機能の確認状態を根拠の範囲と合わせて読む](figures/ch12-coverage-status.png)

| 表示 | 読み方 |
|---|---|
| 操作を確認 | 現行版の画面操作と利用者に見える結果を確認できる |
| 一部対応 | 操作経路や結果の一部を確認できるが、MSP相当の全範囲は未確認 |
| 未確認 | 根拠が足りず、現行版での対応有無や結果を判断できない |
| 未実装 | 対象範囲を調べ、現行版にその操作がないと確認できる |
| 対象外 | 製品の目標範囲に含めていない |

## 学習対象に含めるテーマ

次のテーマは、MSPの一般的な教科書で扱われるため、本書の学習範囲に含めます。現行版の詳細なUIや結果が確認できない項目は「未確認」とします。

| テーマ | 本書での案内 | microProject側の確認状況 |
|---|---|---|
| 開始日・期間・カレンダー・制約 | 第3章の基本操作 | 現行UIで操作可能。MSPとの全条件の同等性は別途確認が必要 |
| 手動／自動スケジュール、締切 | 第9章 | タスクモードとAdvancedの期限欄あり。期限のUndo・MPO保存検証あり。MSPとの全変換挙動は部分確認 |
| 定期タスク | 第9章 | 挿入経路とモデルあり。全繰り返し条件・保存後の動作は確認が必要[^1] |
| 依存関係とクリティカルパス | 第3章 | 基本操作あり。リンク種別、制約、カレンダー全組合せの互換性確認は継続中 |
| リソースの登録・割り当て・平準化 | 第4章 | 基本操作あり。一部の平準化設定と境界条件は互換性確認中 |
| 基準計画、実績、進捗、差異 | 第5章 | 基準計画と進捗のモデル・画面あり。全操作のMSP相当性は確認中 |
| コスト、予算、出来高（EVM） | 第10章 | タスク／プロジェクトEVMプリセットあり。PV・EV・ACは基準計画、進捗・実績作業、単価・固定費から計算する読み取り専用値。ステータス日が時間配分計算の上限。カスタムレポートにEVM列あり。MPOで7値とステータス日の再読込を確認。レポートの物理プレビュー／CSV確認は未完了。通貨換算・値ごとの通貨保持はしない |
| フィルター、グループ、並べ替え、カスタムフィールド、テーブル | 第11章 | 一部の操作とテストあり。全フィールド・複合条件・ビューへの適用範囲は確認中 |
| タイムライン、レポート、印刷 | 第6・11章 | レポートと印刷の機能あり。MSPの既成レポート・タイムライン編集との対応は一部確認中[^2] |
| 複数ウィンドウ、マスター、外部依存、共有リソース | 第7章 | ローカルの複数プロジェクト機能あり。機能ごとに別の操作として確認する |
| CCPM | 第8章 | microProject独自機能。MSP標準機能との互換性機能としては扱わない |

MSPのオンラインサービスや、Project Server、Planner、Microsoft Project VBA・COM・VSTO等の連携は、本製品のスタンドアロンデスクトップ目標の対象外です。MPPファイルの書き出しも現在の製品方針では対象外です。機能がないだけの項目と、製品目標から明示的に除外した項目を区別します[^3]。

## 機能を利用する前に

操作手順を読むときは、画面にコマンドがあること、モデルに関連項目があること、期待した結果が得られることを区別します。手順を再現し、表示結果、データの変化、保存後の状態まで確認できた範囲を、利用可能な機能として扱います。説明のない操作は、似た名前の別機能から推測しません。

資料や画面で操作を確認できないだけでは、未実装とは判断できません。根拠が足りない場合は「未確認」とし、現行版と対象範囲を調べて操作がないと確かめた場合に「未実装」とします。製品の目標範囲外である「対象外」とも区別します。こうして機能の状態と製品の対象範囲を分け、利用可能な操作を判断しやすくします。

:::quiz
Q: マイクロプロジェクトに内部クラスやモデル項目があるだけで、MSPと同じ機能が提供されていると言えますか。
A: いいえ。利用者がたどる操作、計算結果、保存・再読込まで確認する必要があります。
Q: 製品目標から除外された機能と、単に対応状況が未確認の機能はどう扱いますか。
A: 製品範囲に含まれない機能は「対象外」、対応有無を判断する根拠が足りないものは「未確認」、現行版で操作がないと確認したものは「未実装」とします。
:::

:::exercise 機能の状態を調べる
あなたのチームが必要とする機能を三つ選びます。現行版で実際の画面操作と結果を確認し、判断材料が足りない場合は対象範囲と根拠を調べます。それぞれ「操作を確認」「一部対応」「未確認」「未実装」「対象外」のいずれかに分類してください。
:::answer
機能の存在は、画面のボタン名やソースのクラス名だけで判定しません。操作の事前条件、結果、Undo／Redo、MPO保存・再読込、現行受け入れ証跡を合わせて確認します。対象外は理由を記録し、未確認と同じ一覧に埋め込まないようにします。
:::
