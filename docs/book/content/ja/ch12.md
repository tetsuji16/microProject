計画は、タスクを入力した時点では完成ではありません。作業の順序と担当、日程、進捗を見直し、ファイルを保存して開き直し、受け取る人が内容を読み取れる形に整えて仕上げます。この章では、本書で扱った操作を一つの確認手順にまとめます。

## 保存前に計画を見直す

1. タスク表で、成果が分かるタスク名、期間、先行タスク、担当者を確認します。
2. ガントでタスクの順序と開始・終了日を読み、依存関係に沿った計画になっているか確認します。
3. 進捗を更新した計画では、実績と残りの見積りを区別し、基準計画と現行日程を見比べます。
4. リソースを割り当てた計画では、担当者の負荷を確認します。CCPMを使った計画では、適用後のガント、クリティカルチェーン、バッファ状況も見直します。

## MPOで保存して開き直す

microProjectの標準保存形式はMPO（`.mpo`）です。作業中の計画を `Ctrl+S` で保存し、ファイルを閉じてから保存したMPOを開き直します。プロジェクト名、タスク、日程、担当、進捗など、今回の計画に必要な情報が残っていることを確認します。CCPMの情報を含む計画もMPOで保存します。

作業中の計画を元に戻せるよう、編集前にエクスプローラーでファイルのコピーを作り、練習や大きな変更にはコピーを使います。保存するときはファイル名と保存先を確認し、別の計画を上書きしないようにします。受け渡し用のファイル名には、計画名や更新日を含めると区別しやすくなります。

## 相手に渡すファイルを選ぶ

ファイル形式は、受け取る人と用途に合わせて選びます。

| 形式 | 用途 |
|---|---|
| MPO（`.mpo`） | microProjectの標準形式。計画を引き続き編集するときに使います。 |
| MPP（`.mpp`） | Microsoft Projectで作成した計画をmicroProjectへ取り込む外部形式です。 |
| Project XML（`.xml`） | Microsoft Projectなど他のアプリと計画をやり取りするときに使います。microProjectで開いて保存できます。 |
| POD（`.pod`） | ProjectLibreの標準形式です。開いて保存できますが、CCPMの設定は保存されません。 |

相手もmicroProjectで計画を編集するなら、MPOを渡します。Microsoft Projectで作成したMPPを受け取ったら、「ファイル」からインポートして内容を確認し、編集を続ける計画はMPOで保存します。Microsoft Projectを使う相手に渡すときは、MPPではなくProject XMLで保存し、相手側で開けることを確認します。PODを受け取った場合も、開いた計画を確認し、以後の編集にはMPOで保存します。共有前に、送付するファイルを開いて計画名と内容を確認します。

複数ファイルを扱うときは、独立した計画を別々に渡す方法と、子ファイルをマスターのアウトラインに表示する方法を使い分けます。マスターを渡す場合は、マスターと子のファイルを一緒に保管し、相手が必要なファイルを開けるようにします。

## 受け渡し時に伝える

ファイルとともに、計画の更新日、基準日、主な前提、次に確認する事項を伝えます。受け取る人が確認しやすいよう、対象のビューを開いてタスク表とガントを見比べます。基準計画や進捗を使っている場合は、どの時点の計画・実績なのかを説明します。社内の合意や変更理由は、チームで使う議事録や計画資料にも残します。

## この章のまとめ

- タスク表、ガント、担当、進捗を見直してから計画を仕上げます。
- MPOで保存し、開き直して必要な情報が残っていることを確かめます。
- 編集・共有にはMPOを使います。MPPは読み込みのみで、Microsoft Projectへ渡すときはProject XMLを使います。
- ファイルと一緒に更新日、基準日、前提を伝えます。

:::exercise 計画を受け渡す
練習用計画をMPOで保存し、ファイルを閉じて開き直します。タスク表とガントを見直し、ファイル名、更新日、計画の前提を添えて受け渡し用のコピーを用意してください。
:::answer
開き直したMPOで計画名と必要なタスク・日程を確認でき、受け渡し用のコピーと更新日・前提を相手に伝えられれば完了です。
:::
