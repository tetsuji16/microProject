日程が計画内でも、投入費用が予算を超えていれば計画は健全とは言えません。コストを追うには、担当者の単価、作業時間、材料費、タスク固定費、実績を同じ通貨と同じ基準日で管理します。Microsoft Projectの一般的なコスト管理では、作業・材料・費用リソース、単価、使用ごとの費用、タスク固定費を組み合わせて予定コストを計算します[^1]。

![PV・EV・ACから差異と効率指数を求める例](figures/ch10-earned-value.png)

## コストを組み立てる

- **作業リソースの単価**：人や設備の時間当たり単価。作業時間と掛け合わせて費用を見積もります。
- **材料リソースの単価**：消費量に対する単価。数量と単価から材料費を見積もります。
- **使用ごとの費用**：作業時間に比例せず、割当ごとなどに発生する費用です。
- **タスク固定費**：外注費や申請費など、担当者の作業時間とは別にタスクへ付ける費用です。
- **コストリソース**：出張、宿泊、設備購入などの金額項目をタスクへ割り当てます。
- **プロジェクト予算**：承認されたコストの上限または目標です。予算と実績を比較するには、費用の範囲と基準日を明確にします。

### MSP型の作業手順

一般的なMSPワークフローでは、まずリソースシートで人・材料・費用の種類を登録し、必要な標準単価や使用ごとの費用を設定します。タスクに担当リソースを割り当て、作業時間から出る費用を確認します。人件費以外のタスク費用は固定費や費用リソースに分けて入力し、計画全体のコストと予算を比較します。単価表を使う場合は、割当側でどの単価が使われているかも確認します[^1]。

この手順はMSPの考え方を示したものです。microProjectでの各入力欄、レートテーブル、費用リソース、プロジェクト予算の操作手順が同等に確認できたという意味ではありません。リソースやコストのクラス、コスト計算クラスが存在することだけでは、利用者向け操作の完成を証明できません。現行の画面で編集できる値、割当後に計算される金額、レポート表示、MPO保存・再読込を個別に確認してください。

## 出来高管理の3つの値

出来高管理（Earned Value Management, EVM）は、計画した仕事の価値、完了した仕事の価値、実際にかかった費用を比較します。

| 記号 | 名称 | 意味 |
|---|---|---|
| PV | Planned Value（計画価値） | 基準日までに完了している予定だった作業の予算価値 |
| EV | Earned Value（出来高） | 実際に完了した作業に割り当てられた予算価値 |
| AC | Actual Cost（実コスト） | 基準日までに実際に使った費用 |

たとえば、基準日までの予定作業が100、実際に完了した作業の予算価値が80、実コストが90だったとします。値は同じ通貨・同じ尺度で比較します。

1. **スケジュール差異** `SV = EV − PV = 80 − 100 = −20`。完了した作業の予算価値が計画より20少ない状態です。
2. **コスト差異** `CV = EV − AC = 80 − 90 = −10`。80の価値を得るのに90使っており、10のコスト超過です。
3. **スケジュール効率指数** `SPI = EV ÷ PV = 80 ÷ 100 = 0.8`。計画価値の80%相当の仕事を終えています。
4. **コスト効率指数** `CPI = EV ÷ AC = 80 ÷ 90`（約0.89）。実コストあたりの予算価値を示します。

既知値を使った検証でも、`EV = 80`、`PV = 100`、`AC = 90`に対し、`SV = −20`、`CV = −10`、`SPI = 0.8`、`CPI = 80 ÷ 90`となります。

この例では、SVとCVはどちらもマイナスなので、計画に対して進捗が遅く、費用も超過しています。SVは「日数」ではなく予算価値の差です。SPIとCPIは1.0未満なら、基準計画との比較で遅れまたはコスト効率の悪化を示します[^2]。

:::why EVMは入力品質に左右される
PVは基準計画、EVは完了量と予算配賦、ACは実コストに依存します。基準計画がない、完了率が現実と違う、基準日がずれている、費用の範囲が揃わない場合、数式が正しくても判断は誤ります。
:::

## microProjectで使う前の検証

microProjectにはタスク用とプロジェクト用のEVMスプレッドシートプリセットがあります。PV・EV・ACは直接入力する値ではなく、基準計画、進捗・実績作業、リソース単価と固定費などから計算される読み取り専用項目です。基準計画を設定し、進捗や実績作業、コストの計算元を整えてから値を確認してください。ステータス日は「ステータス日」コントロールで設定し、時間配分されたEVM計算はその日付を上限として集計されます。

カスタムレポートでは、BCWS（PV）、BCWP（EV）、ACWP（AC）、CV、SV、CPI、SPIを任意列として選べます。ただし、列選択と出力コードの確認は行われていますが、レポート画面の物理操作でプレビュー値とCSV内容を確かめるRobot確認はデスクトップ競合ガードに阻まれて未完了です。これらを物理GUIで確認済みの帳票手順として扱わず、正式な報告に使う前にプレビューとCSVを照合してください。MPOの保存・再読込テストでは、EVMの7値とステータス日が保持されることを確認しています。

コスト値は通貨単位を持たない数値で、全体に一つの通貨設定を表示形式として適用します。MPP、MSPDI、MPOも各値の通貨を保持せず、通貨換算もしません。Microsoft Projectも1プロジェクトにつき1通貨とし、異なる通貨のプロジェクトを統合する前に共通通貨へ換算するよう案内しています[^3]。microProjectでも、異なる通貨のコストをそのまま合算して安全だとはみなせません。

:::quiz
Q: PV、EV、ACはそれぞれ何を表しますか。
A: PVは予定した仕事の予算価値、EVは完了した仕事の予算価値、ACは実際に使った費用です。
Q: SVがマイナス20万円なら、必ず日程が20日遅れていますか。
A: いいえ。SVは金額単位の予算価値差で、遅延日数ではありません。
Q: EVが80万円、ACが90万円のときCPIはいくつですか。
A: `80 ÷ 90`で、約0.89です。
:::

:::exercise 出来高の数値を計算する
基準日までのPVが200万円、EVが180万円、ACが210万円の場合、SV、CV、SPI、CPIを計算し、進捗とコストの状態を文章で説明します。
:::answer
`SV = 180 − 200 = −20万円`、`CV = 180 − 210 = −30万円`、`SPI = 180 ÷ 200 = 0.90`、`CPI = 180 ÷ 210 ≈ 0.86`です。計画より完了した仕事の価値が少なく、コストも超過しています。SVは日数ではありません。
:::
