# CCPM と MS Project 形式ガントチャート入門

この文書は、初めて microProject を使う人が、ガントチャートの表示を読み、CCPM（クリティカルチェーン・プロジェクト管理）を使って遅れを判断するための実習マニュアルです。

実習には [CCPM path comparison 日本語.mpo](../samples/CCPM%20path%20comparison%20日本語.mpo) を使います。英語版は [CCPM path comparison English.mpo](../samples/CCPM%20path%20comparison%20English.mpo) です。

## このサンプルで学べること

- 先行関係が後続タスクの開始日を決めること
- MS Project 形式のガントバーの色と矢印の意味
- CCPM のクリティカルチェーン、プロジェクトバッファ、フィーディングバッファ
- 実績と残りの見積りから遅れを入力し、バッファ消費状況で判断する方法

サンプルは 11 タスクのソフトウェア・リリース計画です。要件整理から方式設計、実装、総合テスト、リリースへ至る主経路と、環境構築・連携テスト、操作手順書・講習会準備などの合流経路を持ちます。

すべてのタスクは未開始（達成率 0%、実際の開始日なし）かつ自動スケジュールです。したがって、後続タスクは先行関係で許可される日より前には開始しません。

## 1. 最初に見る場所：タスク表とガント

サンプルを開くと、左側にタスク表、右側にガントチャートが表示されます。

![タスク表とガント](images/ccpm-scenario-gantt.png)

このサンプルの表は、CCPM の入門に必要な列だけを表示しています。

| 列 | 何を見る・入力するか |
| --- | --- |
| ID / 名前 | 対象タスクを特定する。 |
| 期間 | 当初の作業量を読む。 |
| 達成率 | 実際に完了した割合を入力する。 |
| 残存期間 | 今後必要な期間の見積りを入力する。遅れを日程へ反映する重要な値。 |
| 実際の開始日 | 実際に着手した日を記録する。 |
| 開始 / 終了 | 再計算後の日程がどう変わったかを確認する。 |
| 先行 | 後続タスクの開始条件となる依存関係を確認する。 |
| リソース名 | 同じ担当者に並行作業を割り当てていないかを確認する。 |

「作業時間の達成率」「実際の終了日」「総余裕」は、日常の CCPM 入門には常時不要なため隠しています。工数実績を管理する必要があるときだけ、作業時間の達成率を追加してください。

### 先行関係の読み方

表の「先行」とガント内の矢印は同じ関係を示します。たとえば「方式設計」の先行が「1」の場合、タスク 1「要件整理」が終わるまで開始できません。矢印がバーの右端から次のバーの左端へつながるのは、この終了－開始（FS）関係です。

開始・終了日を直接そろえるのではなく、先行関係、期間、リソースを入力して自動スケジュールに任せるのが基本です。

## 2. MS Project 形式のガントバーの色

ガントの横方向は日付、縦方向はタスクです。バーの左端が開始、右端が終了、長さが予定期間です。色は「遅延しているか」そのものではなく、タスクの種類、進捗、重要度を表します。

| 見た目 | 意味 | その色になる理由 |
| --- | --- | --- |
| 淡い青のバー | 未完了の計画期間 | 開始から終了までのうち、まだ完了していない部分です。達成率 0% ではバー全体が淡青になります。 |
| 濃い青のバー | 完了した部分 | **達成率（% Complete）** の割合だけ、淡青のバーの左側に重ねて表示します。達成率 25% なら約4分の1が濃青です。 |
| 赤い枠・端点 | クリティカルタスク | 余裕がないクリティカルパス上、または CCPM 適用後のクリティカルチェーン上のタスクです。遅延済みを意味するものではありません。 |
| 濃い灰色の要約バー | サマリータスク | 子タスクを集計する親行です。 |
| 灰色の細いバー | ベースライン | 保存済みの基準計画です。現在のバーとの差で日程変化を比較します。 |
| 濃灰色の矢印 | 先行関係 | 先行タスクが後続タスクの開始条件になっていることを表します。 |
| 緑の割当表示 | リソース割当 | タスク本体ではなく、担当リソースの割当を表す表示です。 |

> **赤 = 遅延、ではありません。** 遅れは、後続タスク・プロジェクト終了日の変化と、CCPM のバッファ消費率で判断します。個別に色を手動変更したバーは、その指定を優先します。

## 3. CCPM を適用する

CCPM は、通常の先行関係だけでなく、同じリソースを同時に使えないという制約も考慮します。個々のタスクへ余裕を分散して持たせる代わりに、プロジェクトの終端と経路の合流点へバッファを置いて管理します。

1. リボンの **プロジェクト** を開く。
2. **CCPM 設定** を選ぶ。
3. **クリティカルチェーン・プロジェクト管理を使用する** をオンにする。
4. プロジェクトバッファを設定する。サンプルは `25%`。
5. **プレビュー** を押す。

![CCPM 設定](images/ccpm-scenario-settings.png)

プレビューでは、変更・分割の件数、未解決競合、クリティカルチェーンのタスク数、推奨バッファを確認します。サンプルでは未解決競合は 0 件です。

実案件で同じ人を複数の並行タスクへ割り当てた場合は、ここで競合が現れます。担当者、カレンダー、先行関係を見直してから適用してください。

プレビュー結果を基準計画として承認する場合だけ、**平準化を適用** を押します。これにより CCPM の基準終了日とプロジェクトバッファ量が記録されます。

## 4. CCPM ネットワークを読む

CCPM 設定ダイアログの **CCPM ネットワーク** タブを開きます。

![CCPM ネットワーク](images/ccpm-scenario-network.png)

- 青い実線はタスクの先行関係です。
- 橙色の接続が現れた場合は、共有リソースの競合を解消するために追加された資源制約です。
- 緑の破線は非主経路がチェーンへ合流する位置です。ここはフィーディングバッファの監視点です。

ネットワークでは「終了日に直結する連鎖」と「途中で合流する作業」を分けて確認します。前者の遅れはプロジェクトバッファへ、後者の遅れはまずフィーディングバッファへ影響します。

## 5. 遅れを正しく入力する

遅れを表すには、達成率だけでなく、残りの見積りも更新します。

| 入力値 | 入力する内容 | 主な反映先 |
| --- | --- | --- |
| **達成率** | 基準日時点で実際に完了した割合 | ガントの濃青部分、バッファ消費状況グラフの横軸（プロジェクト進捗） |
| **残存期間 / 残作業** | 現時点の見積りで必要な残りの期間・工数 | 後続タスクの開始日、プロジェクト終了日、グラフの縦軸（バッファ消費） |
| **実際の開始日** | 実際に着手した日 | 実績記録。未完了なら達成率・残存期間と組み合わせる。 |

### 例：方式設計が遅れた場合

「方式設計」が計画では 50% 完了している時点で、実績は 25% であり、残りに当初見積りより 10 稼働日多く必要になったとします。

1. 「方式設計」に実際の開始日と **達成率 25%** を入力する。
2. **残存期間** を、実際に必要な見積りへ 10 稼働日分増やす。
3. 「実装」以降の開始・終了日が後ろへ動くことをガントで確認する。
4. **CCPM 設定** を開き、**プレビュー** を実行する。

**作業時間の達成率（% Work Complete）だけでは遅れを入力できません。** これは割当工数の実績を管理する値です。ガントの完了部分と CCPM グラフの横軸には達成率を使い、日程への遅れは残存期間または残作業で表します。

## 6. バッファ消費状況を判断する

CCPM 設定ダイアログの **バッファ消費状況** タブを開きます。

![バッファ消費状況](images/ccpm-scenario-buffer.png)

グラフの点は次の意味です。

- 横軸：プロジェクト全体の達成率
- 縦軸：プロジェクトバッファの消費率

縦軸は、概念的には次の式です。

`(現在のプロジェクト終了日 − CCPM 基準終了日) ÷ プロジェクトバッファ`

終了日が基準を超えた分だけ点が上へ移動します。バッファを超える遅れは 100% として表示します。達成率だけを更新すると点は主に横へ動きます。残存期間・残作業を更新して終了日が動くと、点は上へ動きます。

| ゾーン | 判断 | 行動 |
| --- | --- | --- |
| 緑（安全） | バッファ消費が進捗に対して小さい | 現在の優先順位を維持する。 |
| 黄（注意） | バッファ消費が進捗に近づく | 次のチェーン作業を準備し、障害・待ちを取り除く。 |
| 赤（対策が必要） | バッファ消費が進捗を大きく上回る | 範囲、担当、順序、追加支援などの回復策を決める。 |

日常の進捗確認では、遅れを入力した後にまず **プレビュー** を使います。すぐに「平準化を適用」すると、遅れを含む計画が新しい基準になり、元のバッファ消費を比較しにくくなります。正式に基準計画を置き換えると決めたときだけ適用してください。

## 7. 毎週の運用チェックリスト

1. 実際の開始日、達成率、残存期間または残作業を更新する。
2. 先行関係に従って後続の開始・終了日が更新されたことを確認する。
3. CCPM のプレビューで未解決競合を確認する。
4. バッファ消費状況のゾーンを確認する。
5. 黄・赤なら、担当の競合、待ち、障害、タスク順序、追加支援を検討する。
6. 計画を正式に再基準化すると決めた場合だけ、平準化を適用して `.mpo` で保存する。
