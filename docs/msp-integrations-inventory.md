# Project desktop automation and extension inventory

**Reviewed:** 2026-10-12 against the repository source and shared working tree.
**Scope:** M4 local automation/extensions and the local file/master-project portions of #774. This is a source audit, not a product compatibility claim or a live-service test.

The repository currently implements a standalone desktop application with local file exchange. The product goal excludes Project Server, PWA, Project Online, online Microsoft Planner, and other connected-service authentication, synchronization, publishing, and service APIs. Do not add connected-service imports, clients, or dependencies. An importer/exporter, local linked project, model field named `server`, or serializable server-shaped DTO is not a connected service. Local project files, master/linked projects, shared resources, offline collaboration, and local automation/extensions remain separate in-scope desktop behaviors. Native MPO and frozen POD remain first-class project formats; this audit does not authorize weakening or removing either format.

## Source-level route notes for #774

- **Ordinary Open/Save:** `ProjectLoadWorkflow.prepareLoadOptions` marks the route local, and `ProjectFilePolicies` selects POD, MPO, or an external file importer by filename. `LocalSession.getLoadProjectJob` opens a resolved file path and selects an importer; descriptor enumeration scans local native files. This is the active supported Open workflow.
- **Legacy startup/login:** `ApplicationStartupFactory.ensureSupportedOptions` rejects `serverUrl`, `projectId`, and `credentials`. The UI tests assert those command-line forms are rejected. `SessionFactory` retains credential accessors but routes all session requests to a local session; these retained symbols do not connect to a server.
- **Legacy serialized importer route:** `LocalSession.SERVER_LOCAL_PROJECT_IMPORTER` (`server-local`) is registered to `ServerLocalFileImporter`; POD importer-class aliases also map old serialized identifiers to the correct factories. `ServerLocalFileImporter` calls `SafeObjectInput` and `Serializer`, sets model flags, and handles resource mapping. It does not open a socket or issue a remote request. Retain this compatibility route until POD fixtures and all serialized-option callers prove it unnecessary.
- **Master/copy:** `GraphicManager` retains local master-project creation, linked child insertion/opening and detach flows. MPO code persists child references and portable payloads. These are independent of the removed server login route and are not candidates for deletion as “server leftovers.”
- **Serialization namespace:** `com.microproject.server.data` still carries `ProjectData`, `TaskData`, resource and serializer structures. Some are used by native POD data or external conversion. The package namespace is not evidence of live server transport and cannot be removed based on a text search.
- **Planner naming:** `.planner` is the GNOME Planner file format (`File.planner=Gnome Planner`), not Microsoft Planner. Its reader/writer is an actual file interchange capability with incomplete semantic verification. It does not provide authenticated Microsoft Planner access or synchronization. The local Team Planner view is also not a server connection. Use the exchange inventory's explicit reader/writer status.

## Microsoft source basis

The Microsoft [Project client programming overview](https://learn.microsoft.com/en-us/office/client-developer/project/project-client-programming) documents VBA macros, the Project VBA/interop object model, VSTO, and task-pane add-ins. Microsoft's [Project add-ins documentation](https://learn.microsoft.com/en-us/office/dev/add-ins/project/project-add-ins) describes the Common API, manifest and web application model, and notes its limits; it also says Project Server Subscription Edition removed ProjectData OData and Project Online retired September 30, 2026.

Microsoft's [Project Online desktop connection instructions](https://learn.microsoft.com/en-us/projectonline/connect-to-project-online-with-the-project-online-desktop-client) describe the PWA account URL and account selection workflow and mark Project Online retirement on September 30, 2026. The current [Project Server Subscription Edition requirements](https://learn.microsoft.com/en-us/project/software-requirements-project-server-subscription-edition) identify Project Server as a SharePoint Server Subscription Edition Enterprise component and list compatible Project desktop clients.

Microsoft's [Project for the web and Project desktop comparison](https://support.microsoft.com/en-us/project/project-for-the-web-and-project-online-desktop-client) says Project desktop does not connect directly to Project for the web. The current [Planner FAQ](https://support.microsoft.com/en-us/planner/frequently-asked-questions-about-microsoft-planner) says importing `.mpp` is not available in Planner itself and directs that workflow to Planner Power App. These sources support distinguishing a file import/export from live Planner integration; they do not establish the semantic completeness of this application's Planner interchange.

## Decision and remaining acceptance work

This report records the source inventory for M4 and the local file/master-project parts of #774; it is not a milestone or issue closure. Connected Microsoft server/cloud integrations are outside the standalone product goal and are not blockers. M4 remains open because VBA/macros, COM automation/add-ins, VSTO and local Office add-ins are unsupported or unverified. GNOME Planner file semantic coverage remains incomplete, and no external service test is relevant to this product goal.

No adapter deletion or protocol shim is justified by this source audit. Preserve local project file/master-project behavior and fixed-POD compatibility fixtures. Follow-on M4 acceptance requires an explicit inventory and implementation/verification decision for local VBA/macros, COM automation/add-ins, VSTO and Office add-ins. Separately, add a semantic GNOME Planner file round-trip manifest for the wired reader/writer. Keep `server-local` importer IDs, serialized aliases, and `com.microproject.server.data` DTOs until fixed-POD fixtures and callers prove a change safe; their historical names do not justify deleting file/serialization compatibility. Do not add connected-service imports, clients, or dependencies.
