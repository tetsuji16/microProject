# Regression investigation notes

This is the canonical short log of confirmed test findings that are easy to
re-investigate incorrectly. It supplements the live acceptance rules in
[`TEST_PLAN.md`](../../TEST_PLAN.md), [`gui-quality-gate.md`](../gui-quality-gate.md),
and [`gui-recovery-sequence.md`](../gui-recovery-sequence.md); it does not replace
their gates. Recheck the cited source, test, and run when the implementation or
fixture changes. Keep confirmed causes separate from hypotheses.

## Confirmed findings

| Area | Finding and first useful check | Avoid | Regression/evidence |
|---|---|---|---|
| Forked test time zone | Gradle `--system-prop user.timezone=...` did not prove the forked test JVM zone. Set `systemProperty("user.timezone", zone)` on `Test` tasks through a temporary init script, log `TimeZone.getDefault().getID()`/`ZoneId`, and force execution (`--rerun-tasks` or distinct outputs) when switching zones. | Reusing `UP-TO-DATE` results or assuming a command-line system property reached the test worker. | `MpxExportTrackingTest` wall-clock tests; commit `0c8cabaab`; UTC, Tokyo, and Los Angeles runs were compared with actual worker-zone output. |
| MSPDI dates | MSPDI local date-times are floating wall times. Compare raw XML strings with MPXJ parse values and microProject model-wall-as-UTC values before judging an offset. `DateTime.calendarInstance()` is UTC, so `DateTime.fromGmt(...)` is an identity regardless of its conversion flag; use the single `TimeUtil.removeTimeZoneOffset`-based export conversion for task/project date fields. | Treating a parser `Date` instant as the original local timestamp, changing expected dates to match output, or assuming `fromGmt` applies the host offset. | `MpxExportTrackingTest.microsoftXmlRoundTripKeepsTaskBeforeProjectHeaderStart` asserts the parsed constraint and project-header start. The worker-zone assertion passed under UTC, Asia/Tokyo, and America/Los_Angeles with `--rerun-tasks`; changes are in M3 checkpoint `d6edcc4be`. |
| Zero-work assignment units | `Assignment.setWork(0, null)` used to reset a zero-work assignment's explicit units to 1.0. A zero-to-zero request with zero actual work is an identity operation; preserve units, contour, and schedule. Nonzero-to-zero and actual-work paths remain distinct. | Forcing units after import or adding exporter-only unit patches. | `AssignmentContourBehaviorTest.settingAlreadyZeroWorkPreservesExplicitAssignmentUnits` covers 0, 0.5, 1, and 2; `MpoFileImporterTest.separateJvmAssignmentAddsWithDifferentUnitsConflict` verifies independent MPO save/reopen. Verified with JDK 25: `:microproject_core:test --tests "com.microproject.pm.assignment.AssignmentContourBehaviorTest" --console=plain`, then `:microproject_core:test --console=plain` (BUILD SUCCESSFUL, 8 tasks: 1 executed, 7 up-to-date), and `:microproject_exchange:test --console=plain` (BUILD SUCCESSFUL, 10 tasks: 1 executed, 9 up-to-date). Current working tree; M3 patch uncommitted. |
| MSPDI elapsed baselines | The MPXJ MSPDI reader can normalize an elapsed task baseline to working duration. Preserve the source `Duration` and `DurationFormat` through the existing secure XML parse; map elapsed formats with the core elapsed-unit factors. A task baseline with `DurationFormat=8` and `PT48H0M0S` is 2 elapsed days on import, XML export, and reimport. | Trusting MPXJ's normalized baseline getter as the source value, or treating its 6-working-day result as the product contract. | `MpxExportTrackingTest.literalMspdiElapsedBaselineDurationUsesTaskDurationFormat` and `mspdiElapsedBaselineDurationUsesDeclaredFormatAfterMpxjRoundTrip`; latest verified with `:microproject_exchange:test --console=plain` (BUILD SUCCESSFUL, 10 tasks: 2 executed, 8 up-to-date). Microsoft source: [DurationFormat element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/durationformat-element?view=project-client-2016), accessed 2026-10-13. |
| GUI collapse route | A physical collapse test must assert both the spreadsheet and Gantt begin visible and expanded, select through the row-header route, then verify the mutation after rendering. `NO_CHANGE` is correct when the model is already collapsed; the test's starting state must be established through the real expansion route. | Weakening `CommandOutcome`, directly setting a collapsed flag, or guessing that an icon hit caused a no-op without evidence. | `TaskInformationRibbonGuiAcceptanceTest.collapseAndExpandSelectedSummaryChangesVisibleRows`; commit `9ac42ff8e`. |
| Resource sort selection | Snapshot selected resource nodes, clear JTable row selection before changing the visible projection, then restore by resource identity. Sort emits row-insert events synchronously; leaving an old selected row in place lets JTable shift it beyond the new projection and selection listeners may dereference that invalid row before a later clear. First check selected row/node identity immediately before sort and compare it with the published projection; displayed order alone is not proof. | Clamping invalid selection rows or clearing only after sorter update; both hide or preserve the stale intermediate selection. | `ResourceHeaderSortingGuiAcceptanceTest.physicalHeaderClickSortsAndTogglesWithoutMutatingResources` asserts stable empty/equal sort order, pre-sort selection identity, in-range post-sort rows and restored identity. JDK 25 command: `:microproject_ui:guiTest --tests "com.microproject.pm.graphic.views.ResourceHeaderSortingGuiAcceptanceTest.physicalHeaderClickSortsAndTogglesWithoutMutatingResources" -PguiTestLocale=ja -PguiTestUiScale=1 --max-workers=1 --no-daemon --console=plain` (physical PASS at ja/100%); `:microproject_ui:test --console=plain --max-workers=1 --no-daemon` (BUILD SUCCESSFUL, 1m06s). |

## Open or unconfirmed findings

- Windows full GUI run [#461 / run 38270958715](https://github.com/tetsuji16/ProjectLibre/actions/runs/38270958715) (evidence artifact [11757887703](https://github.com/tetsuji16/ProjectLibre/actions/runs/38270958715/artifacts/11757887703)) failed `TaskInformationRibbonGuiAcceptanceTest.markOnTrackRibbonIsDisabledWithoutTaskSelection` only in `visual-ja-1.25` and `visual-ja-1.5`; all three English scales passed. CI uses a 1920×1080 desktop; the local virtual display is 2560×1440. The earlier 1600×700 local pass used a direct button, so it did not cover overflow. The retained test now resizes through the normal window route to 720×700, asserts the actual width and visible overflow-popup ancestor, then physically clicks the disabled command. This passed once at ja/125% on commit `c9cc948ba` with the overflow route established. It verifies that route and its precondition, but does not reproduce or explain the original popup disappearance. Full GUI run #469 passed the matrix on commit `3a70041` ([run 38320038198](https://github.com/tetsuji16/ProjectLibre/actions/runs/38320038198)); that pass did not establish the original failure's cause. The lock-recovery save test passed in all six original CI legs. Do not claim the original CI issue fixed or attribute it to an icon hit.
- A first custom-contour probe used `TimephasedData/Unit=3` as hours. That was invalid: Microsoft defines 3 as weeks (hours is 1; days is 2). After correcting to `Unit=2`, the two-day MSPDI fixture still produced MPXJ buckets 1h and 7h from literal daily values 2h and 6h while conserving 8h total. The difference is unexplained; compare literal XML, MPXJ objects, and model buckets separately before implementing custom contours. Microsoft refs: [Unit element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/unit-element?view=project-client-2016), [Value element](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/value-element?view=project-client-2016), [TimephasedData type](https://learn.microsoft.com/en-us/office-project/xml-data-interchange/timephaseddatatype-elements-and-xml-structure?view=project-client-2016).
