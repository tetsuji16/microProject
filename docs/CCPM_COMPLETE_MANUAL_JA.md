# microProject CCPM 詳細操作マニュアル

このマニュアルは、microProjectで空のプロジェクトを作成し、タスク・先行関係・リソースを入力し、CCPM（クリティカル・チェーン・プロジェクト管理）を適用して、ネットワーク図とバッファ消費グラフを確認し、MPO形式で保存・再読込するまでを記録します。

対象はWindows版の日本語UIです。画面の大きさ、Windowsの表示倍率、microProjectのバージョンによってボタンの位置や文字の省略表示が変わる場合があります。

## 1. この手順で作成するもの

この手順では、次のような導入プロジェクトを作成します。

| 項目 | 内容 |
|---|---|
| プロジェクト | CCPM操作確認プロジェクト |
| タスク数 | 20件程度 |
| 開始日 | 2026年7月1日を例にする |
| 依存関係 | 先行タスクを設定した直列・合流経路 |
| リソース | 同じ担当者を複数タスクへ割り当て、競合を作る |
| 出力 | CCPM設定、ベースライン、ネットワーク、バッファ履歴を含む `.mpo` |

CCPMは、単なるタスクの達成率表示ではありません。タスクの依存関係に加えて、同じリソースを同時に使う競合を考慮し、チェーンとバッファを確認するための機能です。

## 2. 起動と画面の準備

1. リポジトリのルートで `scripts\\run_micrproject_clean.bat` を実行します。
2. 起動したmicroProjectを最大化します。
3. 自動保存が有効になっている場合でも、CCPM固有情報を確実に残すため、最後に必ず「名前を付けて保存」を実行します。
4. 画面撮影時はmicroProjectのウィンドウだけが写る状態にします。

> 以下の画像は、microProjectの実際の画面を撮影したものです。タスク表、CCPM設定、ネットワーク、バッファ状況の順に、操作の確認用として掲載しています。

## 3. 空のプロジェクトを作成する

### 3.1 「新規」を実行する

1. リボンの「ファイル」タブを開きます。
2. 「新規」をクリックします。
3. 新しいプロジェクトの入力画面が表示されたら、プロジェクト名を入力します。
4. プロジェクト名に `CCPM操作確認プロジェクト` と入力します。
5. 作成またはOKを押します。

新規作成直後は、タスク表に入力行が表示されます。タスク名が空欄の行は、まだタスクとして確定していない入力行です。

### 3.2 プロジェクトの開始日を確認する

1. 「プロジェクト」タブを開きます。
2. 「プロジェクトダイアログ」またはプロジェクト情報を開きます。
3. プロジェクト開始日を確認します。
4. このマニュアルと同じ結果にする場合は、開始日を `2026/07/01` にします。
5. 終了日はタスク入力後に再計算されるため、ここでは固定しません。
6. ダイアログを閉じます。

## 4. タスクを入力する

### 4.1 最低限の入力項目

各タスクについて、次の列を入力します。

| 列 | 入力内容 | 注意点 |
|---|---|---|
| 名前 | 作業名 | 空欄のままにしない |
| 期間 | 作業期間 | 日単位の例は1〜10日 |
| 達成率 | 0〜100% | 未着手は0% |
| 開始・終了 | 通常は自動計算 | 先行関係を入力してから確認 |
| 先行 | 先行タスクID | タスク名ではなくIDを入力 |
| リソース名 | 担当者・チーム | 同じリソースを複数タスクに割り当てると競合を作れる |

### 4.3 表への入力手順

1. タスク表の「名前」セルをクリックします。
2. タスク名を入力してEnterを押します。
3. 次の行へ移動し、同じ操作を繰り返します。
4. 必要な行が足りない場合は、行を選択してInsertキーを押します。
5. 「期間」列に期間を入力します。
6. 「先行」列に先行タスクのIDを入力します。
7. 複数の先行タスクがある場合は、画面が受け付ける区切り形式に従って入力します。入力後、エラー表示がないことを確認します。
8. 「リソース名」列に担当者を入力します。
9. 20行分を入力したら、行番号、先行ID、期間、リソース名を見直します。

入力後の実画面例です。

![20タスクを入力したタスク表](images/ccpm-gui-tasks20.png)

確認ポイント：

- タスク名が連続している
- 先行列に存在しないIDがない
- 開始日・終了日が空欄または異常値になっていない
- 同じリソースを複数タスクに割り当てている
- まだCCPMを適用していない段階では、通常スケジュールを原本として扱う

## 5. CCPM設定を開く

### 5.1 設定画面を開く

1. 「プロジェクト」タブをクリックします。
2. 「CCPM設定」をクリックします。
3. 「リソースの平準化」タブが表示されます。

設定画面の実画面例です。

![CCPM設定と平準化画面](images/ccpm-scenario-settings.png)

### 5.2 CCPMを有効にする

1. 「クリティカルチェーン・プロジェクト管理を使用する」にチェックを入れます。
2. プロジェクトバッファの割合を確認します。
3. 初回確認では、例として25%を使用します。
4. リソース一覧に担当者が表示されていることを確認します。
5. 対象リソースを選択します。

リソースが表示されない場合は、タスク表の「リソース名」入力と、リソース一覧への登録状態を確認してください。リソース競合がない計画では、CCPMのチェーンが通常の依存関係中心になることがあります。

## 6. プレビューを実行する

1. 設定画面下部の「プレビュー」をクリックします。
2. 計算が完了するまで待ちます。
3. 画面下部のステータスを確認します。

確認する項目：

- 変更されたタスク件数
- 分割されたタスク件数
- 未解決の競合件数
- クリティカル・チェーンの対象タスク数
- 推奨プロジェクトバッファ
- 平準化後の開始日と遅延日数

### 6.1 プレビュー結果の判断

| 状態 | 判断 |
|---|---|
| 変更0件・競合0件 | 依存関係またはリソース競合がない可能性がある。入力を確認する |
| 変更あり・競合0件 | 適用候補。平準化後の日付を確認する |
| 未解決競合あり | リソース割当、期間、平準化条件を見直す |
| タスクが対象外 | 先行関係、リソース、固定日、読み取り専用状態を確認する |

プレビューは確認用です。内容を採用するまでは、平準化適用を押さないでください。

## 7. CCPMを適用する

1. プレビュー結果を確認します。
2. 未解決の競合がないことを確認します。
3. 「平準化を適用」をクリックします。
4. 確認ダイアログが表示された場合は、変更対象と変更後の日付を確認して確定します。
5. 適用後、タスク表とガントの開始日・終了日が再計算されたことを確認します。
6. 「閉じる」をクリックします。

適用後は、通常のタスク表だけでなく、CCPMのベースライン、チェーン、バッファ情報がプロジェクト状態に保存されます。

### 7.1 適用後に確認すること

- 先行タスクより前に後続タスクが開始していない
- 同じリソースの重複使用が解消または調整されている
- 元のタスク名・期間・達成率が意図せず変更されていない
- プレビューで確認した変更と実際の変更が一致している
- 必要ならCtrl+Zで戻し、Ctrl+Yで再適用できる

## 8. CCPMネットワークを表示する

### 8.1 開き方

次のどちらかを使います。

- キーボード：`Ctrl+Shift+N`
- リボンまたはメニュー：「CCPMネットワーク」／「クリティカルチェーン」

ネットワーク画面の実画面例です。

![CCPMネットワーク図](images/ccpm-gui-network20.png)

### 8.2 ネットワークの読み方

- 四角いノード：タスク
- ノード内の番号：タスクID
- 青い矢印：依存関係またはチェーンの接続
- 緑の点線：フィーディング側からの接続やバッファ関連の接続
- 連続して右へつながるノード：主なチェーン候補
- 独立しているノード：他のタスクと依存していない経路

横幅が広い場合は、ネットワーク内のスクロールバーを使います。画面の一部しか見えていない場合は、図が空なのではなく、スクロール範囲の外にノードがある可能性があります。

## 9. CCPMバッファ状況を表示する

### 9.1 開き方

次のどちらかを使います。

- キーボード：`Ctrl+Shift+K`
- リボンまたはメニュー：「CCPMバッファ状況」

バッファグラフの実画面例です。

![CCPMバッファ消費状況](images/ccpm-gui-buffer20.png)

### 9.2 軸の意味

横軸は時間ではありません。

| 軸 | 意味 |
|---|---|
| 横軸 | プロジェクト進捗率 |
| 縦軸 | バッファ消費率 |
| 点のラベル | `プロジェクト進捗率 / バッファ消費率` |

例えば `50% / 55%` は、「プロジェクト進捗50%、バッファ消費55%」という意味です。日付が50%から75%へ戻ったという意味ではありません。

### 9.3 色の意味

- 緑（安全）：進捗に対してバッファ消費が許容範囲
- 黄（注意）：バッファ消費が進捗に対して高く、確認が必要
- 赤（対策が必要）：遅延回復や計画見直しが必要

境界線は横一直線ではなく、進捗率に応じて斜めに変化します。したがって、同じ消費率でも進捗率によってゾーンが変わることがあります。

## 10. 履歴を使った週次確認

CCPMバッファ状況を開くと、観測点がプロジェクトの履歴として保持されます。例として、次の4点を確認できます。

| 観測順 | 進捗 | バッファ消費 | 解釈 |
|---:|---:|---:|---|
| 1 | 0% | 0% | 開始時点 |
| 2 | 25% | 20% | 順調な進行 |
| 3 | 50% | 55% | 消費が進み注意領域へ接近 |
| 4 | 75% | 30% | 対策後に消費が回復 |

運用では、週次レビューごとに次を行います。

1. タスクの実績達成率を更新します。
2. 残存期間を現実的な見積りへ更新します。
3. 遅延理由、担当者、依存関係を確認します。
4. `Ctrl+Shift+K`でバッファ状況を開き直します。
5. 新しい点が追加されたことを確認します。
6. 点のゾーンが緑・黄・赤のどこにあるかを確認します。
7. 赤または急上昇の場合は、回復策を決めてから計画を更新します。

### 10.1 正しい折れ線の見方

履歴が次の順なら、線は隣り合う点だけを結びます。

```text
0/0 → 25/20 → 50/55 → 75/30
```

`50/55`から`75/30`へ下がるのは、進捗が進んだ後にバッファ消費が改善したことを表します。グラフ上に履歴にない直接線が表示される場合は、保存データを編集せず、まずアプリを最新版へ更新して再読込してください。

## 11. ネットワークとバッファを同時に確認する

1. ネットワークで、遅れているタスクがどのチェーンに属するか確認します。
2. 同じリソースが複数経路に現れていないか確認します。
3. バッファグラフで、進捗に対する消費の割合を確認します。
4. ネットワーク上のボトルネックと、バッファ消費の上昇が一致しているか確認します。
5. 一致しない場合は、達成率、残存期間、実績日、カレンダー、リソース割当を再確認します。

## 12. 保存する

### 12.1 MPO形式で保存する

1. 「ファイル」タブを開きます。
2. 「名前を付けて保存」をクリックします。
3. ファイル名を入力します。例：`CCPM操作確認プロジェクト.mpo`
4. ファイル形式として `.mpo` を選びます。
5. 保存します。

CCPM設定、ベースライン、リソース制約、観測履歴を保持する場合は `.mpo` を使用してください。従来形式の `.pod` ではCCPM固有情報が保持されない場合があります。

### 12.2 保存後に確認する

1. 保存後、タイトルバーのファイル名を確認します。
2. ファイルを閉じます。
3. 「ファイル」→「開く」で、保存した `.mpo` を開きます。
4. タスク名、先行関係、開始日、終了日、リソース名を確認します。
5. 「CCPMネットワーク」を開きます。
6. 「CCPMバッファ状況」を開きます。
7. 保存前のネットワークと履歴点が復元されていることを確認します。

## 13. CSV・HTMLレポートを出力する

1. 「CCPMバッファ状況」を開きます。
2. 下部の「CSV」または「HTML」をクリックします。
3. 保存先とファイル名を指定します。
4. 出力ファイルを開きます。

レポートでは、観測日時、更新者、進捗率、バッファ消費率、ゾーン、ベースラインを週次会議用に確認できます。

## 14. CCPMを解除する

計画を適用した後に元の通常スケジュールへ戻す場合は、解除操作を使います。

1. 「プロジェクト」タブを開きます。
2. 「CCPMを解除」をクリックします。
3. 確認ダイアログで対象を確認します。
4. 実行後、CCPMによる平準化遅延やバッファ表示が解除されたことを確認します。
5. 必要ならCtrl+Zで解除を取り消します。

解除前に、MPO形式で保存しておくことを推奨します。

## 15. よくある問題と確認順序

### 15.1 CCPMネットワークが空になる

1. CCPM設定が有効か確認します。
2. 「平準化を適用」を実行したか確認します。
3. ベースラインが作成されているか確認します。
4. タスクに先行関係があるか確認します。
5. リソースが登録・割り当てされているか確認します。
6. 別のプロジェクトを表示していないか確認します。

### 15.2 バッファグラフが空になる

1. CCPM計画が適用済みか確認します。
2. `Ctrl+Shift+K`を再実行します。
3. プロジェクトにタスクがあるか確認します。
4. 設定画面のCCPMチェックが外れていないか確認します。
5. ファイルを `.mpo` で保存したか確認します。

### 15.3 先行関係エラーになる

- 先行列にはタスク名ではなくタスクIDを入力します。
- 存在しないIDを入力しないでください。
- 削除したタスクのIDが残っていないか確認します。
- 複数先行の区切り形式を、現在の画面が受け付ける形式に合わせます。

### 15.4 日付が戻ったように見える

バッファグラフの横軸は日付ではなくプロジェクト進捗率です。日付を確認する場合は、タスク表の開始・終了列またはガントチャートを確認します。

### 15.5 バッファ消費率が下がる

進捗率が上がり、残存期間や遅延が改善した場合、バッファ消費率が下がることがあります。これは必ずしも誤りではありません。履歴点のラベルと、タスクの実績・残存期間を同じレビュー時点で比較してください。
